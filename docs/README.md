# Repository documentation

Product documentation lives in the documentation site, under
[`apps/docs`](../apps/docs). Getting started, the concept guides and the
migration guide are all there, and it is where user-facing writing belongs.

This directory holds maintainer and history material, plus one generated
artifact.

- [Releasing](releasing.md): the runbook for the changesets pipeline, the
  protected publish gate and recovery from a partial release.
- [adr](adr/): design records. They document decisions as they were made and
  are not maintained as current documentation.
- [plans](plans/): implementation plans. They describe the repository as it
  was when each was written, including paths and package names that have since
  changed.
- [api](api/): TypeDoc output, generated by `pnpm docs`. `pnpm docs:check`
  regenerates it and fails when the committed result differs, which is what
  keeps the published type surface from drifting.

## Two API references, on purpose

`docs/api` is the drift gate described above. The documentation site generates
its own reference from the same five entry points, so readers get one
integrated with the guides and navigation.

They are separate deliberately: changing generation and presentation at once
would make a drift failure hard to attribute. Consolidating them is a later
decision, not an oversight.
